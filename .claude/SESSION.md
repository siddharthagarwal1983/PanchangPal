# Session Objective

Verify that a ritual session survives a process restart — the last free engineering item in B1/B2/B3.

**Answered: yes, now.** It took fixing the gate, reading the verdict, and shipping a fix.

---

# 1. The E2E build was failing — disguised as a timeout (PR #35, merged)

The single-ABI E2E run on the main tip did not slow-build to the timeout as assumed. It **failed in
`assembleRelease` at ~11 min** (`mergeReleaseNativeDebugMetadata` + release lint), then Gradle hung
~80 min on stuck workers until `timeout-minutes: 90` killed the job and it reported `cancelled` — a
red build wearing a timeout's costume, the "gate goes dark" pathology one layer down.

Fixed (workflow-only; `android/` is regenerated by prebuild each run, so CLI flags are the lever):
wrap the build in `timeout --kill-after=2m 40m` + `--stacktrace` so a stuck build fails as a red step
in minutes, and drop release-only work the throwaway emulator APK doesn't need — release lint and
`mergeReleaseNativeDebugMetadata`. Build then went green in ~10 min and the flows finally ran.

---

# 2. The working gate caught the real bug: MMKV v2 vs New Architecture

With the build fixed, `FLOW_SESSION_PERSISTENCE` executed and **failed** — sessions did not survive a
restart. Logcat named the cause: `react-native-mmkv@2.12.2` is incompatible with the New
Architecture's bridgeless runtime, so MMKV's JSI never installed, every instance threw "React Native
is not running on-device", and `ritualSessionRepository` silently degraded to its in-memory fallback.
A dependency-version bug, not a storage-logic bug — the repository code was correct all along.

---

# 3. The fix: MMKV v2 → v4 (PR #36, merged as `e1e10d4`)

`react-native-mmkv` `^2.12.2` → `^4.3.2` (Nitro line, bridgeless-compatible) + its
`react-native-nitro-modules@^0.35.9` peer (resolved 0.35.10). v4 API changes absorbed at the
`KeyValueStore` port boundary so nothing else sees the vendor API: instances via the `createMMKV()`
factory (not `new MMKV()`); `delete()`→`remove()` mapped in `createDeviceStore`. Added a jest manual
mock (`apps/mobile/__mocks__/react-native-mmkv.js`) because v4 eagerly imports nitro, whose
`TurboModuleRegistry.getEnforcing` throws at load in node/jest and crashed every suite; the mock keeps
import side-effect-free and makes `createMMKV` throw exactly as off-device native does.
